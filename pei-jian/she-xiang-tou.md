# 摄像头

## 关于摄像头模块

现有若干款树莓派官方摄像头模块。

- **摄像头模块 1。** 一款 500 万像素摄像头，有标准版（可见光）和 NoIR 版（可见光加红外光）两种版本，视场角（FoV）为标准。树莓派已不再提供该设备。
- [**摄像头模块 2。**](#摄像头模块-2) 一款 800 万像素摄像头，有标准版和 NoIR 版两种版本，视场角（FoV）为标准。
- [**摄像头模块 3。**](#摄像头模块-3) 一款 1200 万像素摄像头，有标准版和 NoIR 版两种版本。标准版和 NoIR 版均有标准视场角（FoV）和广角版本，共四种不同的变体。摄像头模块 3 传感器组件也可单独购买，使你能够将这些功能集成到更小的设备中。
- [**高质量（HQ）摄像头。**](#高质量hq摄像头) 一款 1200 万像素摄像头，配备 CS 卡口或 M12 卡口两种变体，用于搭配外置镜头。该型号没有 NoIR 版本。
- [**AI 摄像头。**](ai-she-xiang-tou.md) 一款 1200 万像素摄像头，可为任何摄像头应用提供低延迟、高性能的 AI 能力。与[树莓派摄像头软件栈](../shu-mei-pai/she-xiang-tou-ruan-jian.md)的紧密集成使用户能够以极少的投入部署自己的神经网络模型。该型号没有 NoIR 版本。
- [**全局快门摄像头。**](#全局快门摄像头) 一款 150 万像素摄像头，采用全局快门机制。它能一次性捕捉场景中每个像素的光线，是拍摄高速运动物体的理想选择。它配备 CS 卡口，用于搭配外置镜头。该型号没有 NoIR 版本。

要比较这些摄像头的硬件特性，请参阅[硬件规格](#硬件规格)。

## 安装树莓派摄像头

安装树莓派摄像头的过程对于各种摄像头和主板的组合基本一致。接口存在一些差异；以下步骤中会说明这些差异。

### 第 1 步：准备

>**警告**
>
> 摄像头对静电敏感。在处理 PCB 之前，请先将自己接地。如果没有接地带，可以触摸水龙头或类似物品来接地。

要完成此过程，你需要以下物品：

* 一块带有摄像头接口的树莓派主板。
* 一个树莓派摄像头。

  有些摄像头的镜头上可能覆有一小片半透明蓝色塑料薄膜。它只是在运输过程中保护镜头。要移除它，请轻轻剥下。

* 用于连接摄像头和主板的合适线缆。
  * 所有树莓派摄像头都使用标准的 15 针接口。
  * 包括树莓派 4 在内的树莓派旗舰型号使用标准的 15 针接口。对于这些主板，请使用摄像头随附的 Standard-Standard 摄像头线缆。
  * 树莓派 5、所有树莓派 Zero 型号和计算模块 IO 板使用迷你的 22 针接口。对于这些主板，请使用 [Standard-Mini 摄像头线缆](https://www.raspberrypi.com/products/camera-cable/)。
  * 有些计算模块开发套件附带一块计算模块摄像头和显示转接板（CMCDA）电路板，它将 IO 板上的迷你 22 针接口转换为标准的 15 针接口。

### 第 2 步：将线缆连接到树莓派

>**注意**
>
> 如果你打算在树莓派 5 上使用主动散热器，请考虑在安装主动散热器之前将线缆连接到树莓派设备上的摄像头接口。安装好主动散热器后，操作摄像头接口可能会不太方便。

1. 关闭树莓派并断开电源。
2. 找到树莓派主板上的摄像头接口。

   以下描述假定你手持树莓派主板时，芯片和接口朝上，树莓派徽标和主板名称方向正确。对于顶面没有徽标的树莓派 Zero 主板，请将 GPIO 排针沿离你最远的边缘摆放。

   * 在树莓派 Zero 设备上，摄像头接口位于右侧的短边，与存储卡插槽相对。
   * 在树莓派 4 之前的树莓派旗舰型号上，摄像头接口位于离你最近的边缘、HDMI 接口和音频插孔之间。它标注为 CAMERA。
   * 在树莓派 4 上，摄像头接口位于离你最近的边缘、micro HDMI 接口和音频插孔之间。它标注为 CAMERA。
   * 在树莓派 5 上，两个摄像头和显示接口位于离你最近的边缘、micro HDMI 接口和以太网口之间。它们标注为 CAM/DISP0 和 CAM/DISP1。你可以使用其中任一接口连接摄像头。
   * 在树莓派计算模块 1/3/3+ IO 板上，两个摄像头接口位于左边缘（IO 板上最靠近徽标的边缘）离你最近的一端。它们标注为 CAM0 和 CAM1。你可以使用其中任一接口连接摄像头。
   * 在树莓派计算模块 4 IO 板上，两个摄像头接口位于最左侧的角落。它们标注为 CAM0 和 CAM1。你可以使用其中任一接口连接摄像头。
   * 在树莓派计算模块 5 IO 板上，两个摄像头接口位于最远边缘的左端。它们标注为 CAM/DISP0 和 CAM/DISP1。你可以使用其中任一接口连接摄像头。

3. 打开接口上的翻盖。
   1. 如果有一条薄膜使接口翻盖保持关闭，请将其移除。
   2. 轻轻地将翻盖从接口中拉出，直到感觉它停止。此时翻盖有一定的活动空间。
   3. 将翻盖稍微向远离接口开口的方向倾斜。
4. 插入摄像头线缆的一端，使金属触点背向翻盖。

   确保摄像头线缆牢固地插入接口中并平直就位，以正确对齐所有触点。注意不要将柔性线缆弯成锐角。

5. 将翻盖向线缆方向翻回，并向下推入接口，直到感觉它咔嗒一声就位。

   翻盖将线缆固定到位，并确保接口引脚与线缆的金属触点之间良好接触。

你可以按相反的顺序执行这些步骤，从接口中移除线缆。

### 第 3 步：将线缆连接到摄像头

我们的摄像头出厂时已连接 Standard-Standard 线缆。如果你已移除此线缆或想改用其他线缆，请完成以下步骤。

摄像头接口位于主板上与镜头相对的一侧。手持摄像头时，使镜头朝下或远离你。

1. 打开接口上的翻盖。
   1. 轻轻地将翻盖从接口中拉出，直到感觉它停止。此时翻盖有一定的活动空间。
   2. 将翻盖稍微向远离接口开口的方向倾斜。
2. 插入摄像头线缆的一端，使金属触点背向翻盖并朝向摄像头主板。

   确保摄像头线缆牢固地插入接口中并平直就位，以正确对齐所有触点。注意不要将柔性线缆弯成锐角。

3. 将翻盖向线缆方向翻回，并向下推入接口，直到感觉它咔嗒一声就位。

   翻盖将线缆固定到位，并确保接口引脚与线缆的金属触点之间良好接触。

你可以按相反的顺序执行这些步骤，从接口中移除线缆。

### 第 4 步：准备软件

1. 将树莓派设备重新接通电源并开机。
2. 按照[保持操作系统最新](../shu-mei-pai/raspberry-pi-os.md#更新当前的树莓派软件)的说明，确保你的内核和应用程序都是最新版本。
3. 按照 [`rpicam-apps`](../shu-mei-pai/she-xiang-tou-ruan-jian.md#rpicam-apps) 的设置说明进行操作。
4. （可选）如果你想使用 Picamera2 Python 库，请按照 [Picamera2 Python 库](https://pip.raspberrypi.com/documents/RP-008156-DS) 的设置说明进行操作。

### 卷帘快门还是全局快门？

大多数数码相机（包括我们的其他摄像头模块）都使用**卷帘快门**：它们逐行扫描正在捕捉的图像，然后输出结果。这在某些情况下可能会造成失真效果。例如，拍摄旋转的螺旋桨叶片时，图像可能看起来像是在闪烁，而不像一个正在旋转的物体。这是因为在相机扫描并观察场景的短暂瞬间，螺旋桨叶片有足够的时间改变位置。

**全局快门**（例如我们的全局快门摄像头模块所用的那种）不会这样做。它一次性捕捉场景中每个像素的光线，因此拍摄螺旋桨叶片等物体不会产生相同的失真。

这很有用，因为像螺旋桨叶片这样的高速运动物体现在很容易捕捉；我们还可以同步多台摄像头，在精确的同一时刻拍摄照片。这样做的好处包括在捕捉立体图像时最大限度减少失真；如果左眼中出现的运动尚未出现在右眼中，人类大脑会感到困惑。在光线充足的情况下，树莓派全局快门摄像头还可以使用比卷帘快门相机更短的曝光时间——低至 30 µs——这使它适用于高速摄影。

>**注意**
>
> 全局快门摄像头的图像传感器具有 6.3 mm 对角线的活动感应区域，大小与树莓派 HQ 摄像头类似。但是，它的像素更大，可以收集更多光线。大像素尺寸和低像素数在机器视觉应用中非常有价值；传感器产生的像素越多，实时处理图像就越困难。为了解决这个问题，许多应用程序会缩小和裁剪图像。使用全局快门摄像头和适当的镜头放大倍率则无此必要，因为较低的分辨率和较大的像素尺寸意味着可以原生捕捉图像。

## 同步捕获

高质量（HQ）摄像头支持同步捕获。一台摄像头（“源摄像头”）可以配置为在开始捕获一帧时，在其 XVS（垂直同步）引脚上产生脉冲。其他（即“接收”）摄像头可以监听此脉冲，并与源摄像头同时捕获帧。

此方法已在很大程度上被[软件摄像头同步](../shu-mei-pai/she-xiang-tou-ruan-jian.md#软件摄像头同步)取代，后者无需额外接线即可远距离工作，并具有亚毫秒级精度。但是，当摄像头物理位置接近时，你可以使用有线同步。

>**注意**
>
> 你也可以在同步模式下操作全局快门（GS）摄像头。但是，源摄像头会多录一帧。对于 GS 摄像头，我们建议改用[外部触发源](#全局快门摄像头的外部触发)。你不能同步 GS 摄像头和 HQ 摄像头。

### 连接摄像头

在每台摄像头的 XVS 测试点上焊接一根导线，并将它们连接在一起。

在每台摄像头的 GND 测试点上焊接一根导线，并将它们连接在一起。

*仅对于 GS 摄像头，* 你还必须将每台摄像头的 XHS（水平同步）测试点连接在一起。在你希望其用作接收摄像头的任何 GS 摄像头上，用焊料将 MAS 焊盘的两半搭接在一起。

>**注意**
>
> 本文档的早期版本建议为 XVS 使用外部上拉电阻。现已不再推荐这样做。请确保你拥有最新版本的树莓派系统，并为所有连接的摄像头设置 `always-on` 属性。

### 驱动程序配置

配置摄像头驱动程序，使其在非流传输期间保持 1.8 V 电源开启，并（可选）选择源摄像头和接收摄像头角色。

#### 对于 HQ 摄像头

编辑 `/boot/firmware/config.txt`。将 `camera_auto_detect=1` 更改为 `camera_auto_detect=0`。

对于源摄像头，追加以下行：

```
dtoverlay=imx477,always-on,sync-source
```

或者对于接收摄像头：

```
dtoverlay=imx477,always-on,sync-sink
```

在树莓派 5、CM4 或 CM5 上使用 CAM0 端口时，请在该行末尾追加 `,cam0`，不要留空格。如果两台摄像头连接在同一台树莓派上，你需要两行 `dtoverlay`，其中只有一行以 `,cam0` 结尾。

或者，如果你希望在运行时切换摄像头的角色（并且它们没有都连接到同一台树莓派上），请省略上面的 `,sync-source` 或 `,sync-sink`。此时你可以在启动每个摄像头之前设置一个模块参数。

对于连接源摄像头的树莓派：

```bash
$ echo 1 | sudo tee /sys/module/imx477/parameters/trigger_mode
```

对于连接接收摄像头的树莓派：

```bash
$ echo 2 | sudo tee /sys/module/imx477/parameters/trigger_mode
```

每次系统启动时都要执行此操作。

#### 对于 GS 摄像头

编辑 `/boot/firmware/config.txt`。将 `camera_auto_detect=1` 更改为 `camera_auto_detect=0`。

无论是源摄像头还是接收摄像头，都追加以下行：

```
dtoverlay=imx296,always-on
```

在树莓派 5、CM4 或 CM5 上使用 CAM0 端口时，请在该行末尾追加 `,cam0`，不要留空格。如果两台摄像头连接在同一台树莓派上，你需要两行 `dtoverlay`，其中只有一行以 `,cam0` 结尾。

在 GS 摄像头上，接收摄像头角色由 MAS 引脚启用，无法通过软件配置（`trigger_mode` 和 `sync-sink` 与[外部触发方法](#全局快门摄像头的外部触发)相关，不得用于此方法）。

### Libcamera 配置

如果摄像头未能在 1 秒内全部启动，`rpicam` 应用程序可能会超时。要防止此问题，请在带有接收摄像头的任何树莓派上编辑一个配置文件。

在树莓派 5 或 CM5 上：

```bash
$ cp /usr/share/libcamera/pipeline/rpi/pisp/example.yaml timeout.yaml
```

在其他树莓派型号上：

```bash
$ cp /usr/share/libcamera/pipeline/rpi/vc4/rpi_apps.yaml timeout.yaml
```

现在编辑该副本。在这两种情况下，删除 `"camera_timeout_value_ms":` 行中的 `#`（注释），并将数字更改为 `60000`（60 秒）。

### 启动摄像头

运行以下命令启动接收摄像头：

```bash
$ export LIBCAMERA_RPI_CONFIG_FILE=timeout.yaml
$ rpicam-vid --frames 300 --qt-preview -o sink.h264
```

等待几秒，然后运行以下命令启动源摄像头：

```bash
$ rpicam-vid --frames 300 --qt-preview -o source.h264
```

帧必须同步。使用 `--frames` 参数确保捕获相同数量的帧，并且录制长度完全相同。先运行接收摄像头可确保不会丢失任何帧。

>**注意**
>
> 在同步模式下使用 GS 摄像头时，接收摄像头录制的帧数与源摄像头不完全相同。**源摄像头在接收摄像头开始录制前会多录一帧**。因此，你需要使用 `--frames` 参数指定接收摄像头少录一帧。

## 全局快门摄像头的外部触发

全局快门（GS）摄像头可以通过向板上的外部触发连接（在板上标记为 XTR）施加脉冲，从外部触发。多台摄像头可以连接到同一个脉冲，从而提供了同步两台摄像头的另一种方式。

曝光时间等于低脉冲宽度加上额外的 14.26 µs。例如，10000 µs 的低脉冲会产生 10014.26 µs 的曝光时间。帧速率直接取决于你向该引脚施加脉冲的频率。30 Hz 的 PWM 频率对应每秒 30 帧的帧速率。

![显示脉冲格式的图片](.gitbook/assets/external_trigger.jpg)

### 准备工作

>**警告**
>
> 此修改包括拆除一个 SMD 焊接部件。除非你觉得自己有能力完成此修改，否则不要尝试。在摄像头板上焊接时，请拆下塑料背盖以避免损坏。

如果你的主板上安装了晶体管 Q2（如下图蓝色所示），则需要从主板上拆除 R11（如下图红色所示）。它将 GP1 连接到 XTR，如果不拆除 R11，摄像头将无法在外部触发模式下工作。元件的位置如下图所示。

![显示待拆除电阻器的图片](.gitbook/assets/resistor.jpg)

接下来，在 GS 摄像头板的 XTR 和 GND 触点上焊接一根导线。请注意，XTR 是 1.8 V 输入，因此你可能需要电平转换器或电位分压器。

我们可以使用树莓派 Pico 来提供触发信号。将任意 Pico GPIO 引脚（本示例使用 GP28）通过 1.5 kΩ 电阻连接到 XTR。还在 XTR 和 GND 之间连接一个 1.8 kΩ 电阻，将高逻辑电平降低到 1.8 V。接线图如下图所示。

![显示树莓派 Pico 接线的图片](.gitbook/assets/pico_wiring.jpg)

#### 树莓派 Pico MicroPython 代码

```python
from machine import Pin, PWM

from time import sleep

pwm = PWM(Pin(28))

framerate = 30
shutter = 6000  # 单位为微秒

frame_length = 1000000 / framerate
pwm.freq(framerate)

pwm.duty_u16(int((1 - (shutter - 14) / frame_length) * 65535))
```

低脉冲宽度等于快门时间，PWM 的频率等于帧速率。

>**注意**
>
> 在本示例中，Pin 28 连接到 GS 摄像头板上的 XTR 触点。

### 摄像头驱动程序配置

仅当你有多台摄像头将 XTR 并联接线时，才需要执行此步骤。

编辑 `/boot/firmware/config.txt`。将 `camera_auto_detect=1` 更改为 `camera_auto_detect=0`。

追加以下行：

```
dtoverlay=imx296,always-on
```

在树莓派 5、CM4 或 CM5 上使用 CAM0 端口时，请在该行末尾追加 `,cam0`，不要留空格。如果两台摄像头都连接到同一台树莓派上，你需要两行 `dtoverlay`，其中只有一行以 `,cam0` 结尾。

如果外部触发不会立即启动，你还需要[如上](#libcamera-配置)所述增加 libcamera 超时时间。

### 启动摄像头

启用外部触发：

```bash
$ echo 1 | sudo tee /sys/module/imx296/parameters/trigger_mode
```

在 Pico 上运行代码，然后启动摄像头：

```bash
$ rpicam-hello -t 0 --qt-preview --shutter 3000
```

每次 Pico 向该引脚发送脉冲时，都会尝试捕获一帧。但是，如果未设置 `--gain` 和 `--awbgains`，则会丢弃一些帧，以便 AGC 和 AWB 算法稳定下来。

>**注意**
>
> 运行 `rpicam-apps` 时，请始终指定固定的快门持续时间，以确保 AGC 不会尝试调整摄像头的快门速度。具体数值并不重要，因为它实际上由外部触发脉冲控制。

## 红外滤光片

高质量（HQ）摄像头和全局快门摄像头都包含一个红外滤光片，用于降低摄像头对红外光的敏感度，并使户外照片看起来更自然。但是，你可以拆除滤光片来：

* 增强某些类型摄影中的色彩，例如植物、水和天空的图像
* 在红外光照明的位置提供夜视功能

### 拆卸滤光片

>**警告**
>
>**此过程不可逆：** 固定滤光片的粘合剂一旦揭起再装回，便无法继续粘牢，而且红外滤光片虽然厚约 1.1 mm，拆除时可能会破裂。**拆除它会使产品保修失效**。

你可以从 HQ 和 GS 摄像头上拆除滤光片。下面的演示展示了 HQ 摄像头。

![安装好滤光片的 HQ 摄像头](.gitbook/assets/FILTER_ON_small.jpg)

>**重要**
>
>传感器暴露在空气中时，请确保在干净无尘的环境中操作，以保护传感器。

1. 拧下主电路板底部的两个 1.5 mm 六角锁紧螺钉。小心不要让垫圈滚开。

   ![拧下六角锁紧螺钉后的摄像头](.gitbook/assets/SCREW_REMOVED_small.jpg)

2. 外壳和 PCB 之间有一层略带粘性的密封垫圈，需要用一点力气才能分开。你也可以尝试一些方法来弱化粘合剂，例如使用少量异丙醇或加热（约 20-30 °C）。
3. 粘合剂松动后，抬起主板并将其放在非常干净的表面上。确保传感器不会接触到表面。

   ![放置在干净表面上的摄像头主板](.gitbook/assets/FLATLAY_small.jpg)

4. 将镜头座翻转使镜头朝上，并将其放在平坦的表面上。

   ![使用溶剂弱化粘合剂](.gitbook/assets/SOLVENT_small.jpg)

5. 为最大限度降低损坏滤光片的风险，请使用笔帽或类似的软塑料物品，仅在玻璃与铝相接的边缘处向下按压滤光片。胶水会断裂，滤光片将从镜头座上脱落。

   ![从镜头座上拆下的滤光片](.gitbook/assets/REMOVE_FILTER_small.jpg)

6. 鉴于更换镜头会使传感器暴露，此时你可以安装一个透明滤光片（例如 OHP 塑料），以尽量减少灰尘进入传感器腔的机会。
7. 将主外壳重新装回电路板上。确保外壳与仍留在电路板上的密封垫圈重新对齐。
8. 先放上尼龙垫圈，以防止损坏电路板。
9. 接着放上钢垫圈，它可以防止尼龙垫圈损坏。拧紧两个六角锁紧螺钉。只要垫圈按正确顺序安装，就不需要拧得很紧。

   ![拆除滤光片后的 HQ 摄像头](.gitbook/assets/FILTER_OFF_small.jpg)

>**注意**
>
> 将滤光片粘回原位并使设备恢复正常光学摄像头的功能，可能很难甚至无法做到。

### 引脚信息

使用本节中的信息来了解摄像头连接器中各个引脚的功能。

#### 找到 1 号引脚

FPC 连接器上 1 号引脚的位置取决于硬件。

以下描述假定你手持树莓派主板时，芯片和接口朝上，树莓派徽标方向正确。对于顶面没有徽标的树莓派 Zero 主板，请将 GPIO 沿离你最远的边缘摆放。

* 在树莓派旗舰型号和树莓派 Zero 设备上，1 号引脚是离你最远且最靠近 GPIO 排针的引脚。
* 在树莓派计算模块 IO 板上，根据型号，1 号引脚用小圆圈或圆点标记。

手持树莓派摄像头板时，使镜头朝下、接口朝向你的右侧，1 号引脚是离你最近的引脚。

#### 摄像头连接器引脚定义（15 针）

这是树莓派 5 之前的旗舰树莓派型号上使用的 15 针摄像头串行接口（CSI）连接器的引脚定义。该连接器与 Amphenol SFW15R-2STE1LF 兼容。

信号方向从树莓派主板的角度指定。I2C 线路（SCL 和 SDA）在树莓派主板上被上拉至 3.3 V。

GPIO 线路的功能和方向取决于所使用的具体摄像头模块。通常，`CAM_IO0` 用作高电平有效的电源使能。某些产品不包含 `CAM_IO1`。

#### 摄像头连接器引脚定义（22 针）

信号方向从树莓派主板的角度指定。I2C 线路（SCL 和 SDA）在树莓派主板上被上拉至 3.3 V。

GPIO 线路的功能和方向取决于所使用的具体摄像头模块。通常，`CAM_IO0` 用作高电平有效的电源使能。某些产品不包含 `CAM_IO1`。

| 引脚 | 名称 | 说明 | 方向/类型 |
| ---- | ---- | ---- | ---- |
